## What this is

**TensorCanvas** is a visual neural-network studio: draw a network on a canvas,
compile it to a real PyTorch model, train it on your own data, then replay the
forward pass neuron-by-neuron and edit weights live to see the effect.

**Mental model:** *a graph compiler with a drawing UI bolted onto each side of a
thin JSON wire format.* The browser draws a graph; the backend compiles it to an
`nn.Module` and runs/trains/inspects it; results stream back over HTTP + SSE.

Monorepo:
```
tensorcanvas/
├── client/        Next.js 16 + React 19 + TS + Tailwind v4 + Zustand + React Flow
├── server/        Python 3.12 + FastAPI + PyTorch (uv-managed)
├── sample-data/   dataset generator + example datasets + alexnet.tcnet.json
├── docs/          extension recipes (add a layer / dataset / pretrained / example)
└── dev.sh         one command to run both
```

## Run / test / build (exact commands)

```bash
./dev.sh                                   # runs backend + frontend together
# frontend → http://localhost:3000   backend → http://localhost:8000 (docs at /docs)

cd server && uv sync                        # backend deps into server/.venv
cd server && uv run tensorcanvas-server     # backend alone
cd server && uv run pytest                  # backend tests (currently 32)

cd client && yarn install                   # frontend deps (Yarn 4 via corepack)
cd client && yarn dev                        # frontend alone
cd client && yarn lint && yarn build         # MUST be clean before any PR
```

**Definition of done for a change:** `uv run pytest` passes, `yarn lint` and
`yarn build` are clean. Add a backend test for new backend behaviour.

## Critical gotchas — read before writing code

1. **Next.js 16 is not the Next.js you were trained on.** APIs/conventions differ.
   Before writing frontend code that touches Next internals, read the relevant
   guide under `client/node_modules/next/dist/docs/`. (`client/AGENTS.md` is
   auto-generated by `next dev` on every run and is git-ignored — don't edit or
   commit it.)
2. **`@xyflow/react` is pinned to `12.12.1` on purpose.** v13 removed/renamed
   runtime APIs we depend on (`applyNodeChanges`, change types). Do **not** bump it.
3. **Package managers are fixed:** frontend uses **Yarn 4** via `corepack enable`
   (see `packageManager` in `client/package.json`); backend uses **uv** (never pip
   directly). Python 3.12.
4. **Adding a layer type touches TWO files** that must agree: backend
   `server/.../builder.py` (`LAYERS` registry) **and** frontend
   `client/components/build/nodeCatalog.ts` (`CATALOG` + `PALETTE_ITEMS`).
   - A drift guard, `server/tests/test_catalog.py`, FAILS if the palette references
     a type the backend can't build. `GET /api/v1/catalog` is the source of truth.
   - **Escape hatch:** the **Custom node** sends an arbitrary backend `type` with no
     frontend change — use it to try a backend-only layer. See
     [docs/adding-a-layer.md](./docs/adding-a-layer.md).
5. **State is in-memory and process-local.** `ModelRegistry`, `RunRegistry`,
   `SnapshotRegistry`, `DatasetRegistry` live in RAM keyed by id; restarting the
   backend loses all built models/snapshots. Not a bug — it's the studio workflow.
6. **Weight-mutation protocol:** every in-place weight change (training step, live
   PATCH, checkpoint restore, pretrained load) happens under
   `ModelRecord.train_lock` and bumps `ModelRecord.weight_version`. Snapshots stamp
   the version they were taken at, so the UI can flag them `stale`. Respect this
   when adding anything that writes weights.
7. **PyTorch is CPU-only here.** Pretrained weights (AlexNet ~233 MB, VGG-16
   ~528 MB) download from torchvision **at runtime on first use** — never bundle
   them, and never trigger the download in tests (keep tests offline).
8. **The backend reads env directly from `os.environ`** (no `.env` autoload):
   `HOST`, `BACKEND_PORT`/`PORT`, `RELOAD`, `CORS_ORIGINS`, `TORCH_HOME`. The client
   reads `NEXT_PUBLIC_API_URL` (must have the `NEXT_PUBLIC_` prefix). See the
   `.env.example` files. No secrets exist in this project.
9. **Pretrained inference is normalized.** `ModelRecord.input_norm` holds the
   ImageNet mean/std; `observe.py` applies it to image inputs. Don't feed raw
   `[0,1]` tensors to pretrained models.

## Conventions

- **API** is under `/api/v1`. FastAPI handlers in `server/.../main.py` are mostly
  sync `def` (run in the threadpool); training streams via SSE (`runs.py`).
- **Wire types are hand-mirrored** and must change together:
  `client/lib/api.ts` ↔ `server/.../schema.py`, and
  `client/lib/trainApi.ts` ↔ `server/.../train_schema.py`.
- **`.tcnet.json`** is the architecture file format (`format: "tensorcanvas-net"`),
  nodes + edges only (no weights). See [docs/tcnet-format.md](./docs/tcnet-format.md).
- **Theme (Tailwind, dark):** sky = weights/primary, violet = activation / observe
  playback, emerald = accuracy / correct, amber = bias / negative values /
  selection. Keep new UI consistent with this.
- **Layer types the backend builds:** `input, output, linear, conv2d, maxpool2d,
  flatten, relu, sigmoid, tanh, softmax`. **Pretrained archs:** `alexnet, vgg16`
  (feedforward only — ResNet's skip connections aren't representable yet).

## Where things live

**Backend** (`server/src/tensorcanvas_server/`): `schema.py` (wire models),
`builder.py` (`LAYERS`, `ACTIVATIONS`, `build_network`, `GraphModule` with
`forward_capture`), `registry.py` (`ModelRecord`), `datasets.py` (loaders +
`match_to_network` + builtins), `train_schema.py`/`training.py`/`runs.py`
(training + SSE), `observe.py` (`run_model`, snapshots, prediction),
`pretrained.py` (`PRETRAINED` registry + `copy_conv_linear_in_order`),
`main.py` (endpoints), `__init__.py:main` (uvicorn entry).

**Frontend** (`client/`): `components/WorkspaceShell.tsx` (tabs),
`components/build/*` (canvas, `FlowNode`, `nodeCatalog.ts`, `edit/LayerEditor.tsx`),
`components/train/*`, `components/observe/*`; state in `lib/store.ts` (`useGraph`),
`lib/trainStore.ts`, `lib/observeStore.ts`; API clients `lib/api.ts`,
`lib/trainApi.ts`, `lib/observeApi.ts`; examples + `.tcnet.json` I/O in
`lib/examples.ts`. Full map + data flows: [ARCHITECTURE.md](./ARCHITECTURE.md).

## Portability (moving machines)

`uv` + Node 20 (`corepack enable`) + Git, then `./dev.sh`. Never copy `.venv/`,
`node_modules/`, or `.next/` — regenerate from `uv.lock` / `yarn.lock`. First
`uv sync` is slow (Torch wheels); pre-warm the pretrained download before a demo.
